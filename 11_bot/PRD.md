# 코드봇 웹서비스 요구사항 명세서

## 1. 목적

사용자가 Python 코드의 일부분을 입력하고 버튼을 누르면, 기존 코드봇이 이어지는 코드를 생성하고 화면에 전체 코드를 표시한다. 기존 모델을 웹에서 호출할 수 있는지 확인하는 최소 기능 제품(MVP)을 만든다.

이 문서를 기준으로 로컬 웹서비스 구현이 추가 승인되었다. 공개 배포는 별도 결정 사항이다.

## 2. 사용자 확정 사항

| 항목 | 확정 내용 |
| --- | --- |
| 이용 대상 | 회원가입과 로그인 없이 누구나 이용 |
| 백엔드 | FastAPI |
| 프론트엔드 | React |
| 모델 | `codebot/model_pretrain.pt` |
| 입력 제한 | 최대 256토큰 |
| 추가 생성 제한 | 최대 256토큰 |
| 문맥 처리 | 기존 코드처럼 최근 256토큰만 참조 |
| 결과 표시 | 입력 코드와 생성된 뒷부분을 합친 전체 코드 |
| 범위 | 코드 입력 → 생성 요청 → 결과 표시의 최소 기능 |
| 추가 결정 | 확정되지 않은 사항은 사용자에게 먼저 질문하고 진행 |

| `03.ipynb` 사전학습 모델 추론 예시 | `max_new_tokens=200`, `temperature=1.0` | 생성 길이는 사용자 확정값으로 변경하고, 나머지 생성 동작은 기존 소스 기준 유지 |
| `generate()`의 문맥 처리 | 길이가 모델 문맥을 초과하면 최근 `model.max_context_len`개 토큰만 모델에 전달 | 입력과 출력의 합계를 256토큰으로 제한할 필요 없음 |
| `generate()`의 반환값 | 입력과 생성 토큰을 함께 디코딩한 전체 문자열 | 반환값을 그대로 전체 코드 결과로 표시; 입력을 다시 덧붙이지 않음 |
| `generate()`의 종료 조건 | 종료 토큰을 만나거나 생성 반복 횟수를 소진하면 종료 | 256토큰보다 짧은 결과도 정상 |

문맥 길이 256은 노트북과 소스에서 확인한 설정이다. 이번 명세 작성 과정에서 `.pt` 체크포인트를 직접 로드하거나 추론을 실행하지는 않았다. 구현 검증 시 `model.max_context_len == 256`인지 확인하고, 다르면 제한 정책을 임의로 바꾸지 않고 사용자에게 확인한다.

## 4. 사용자 흐름과 화면

1. 사용자가 로그인 절차 없이 단일 서비스 화면에 접근한다.
2. 여러 줄을 입력할 수 있는 입력창에 이어쓰기를 원하는 코드를 작성하거나 붙여 넣는다.
3. 사용자가 생성 버튼을 누른다.
4. 서버가 입력을 검증한 뒤 코드봇으로 뒷부분을 생성한다.
5. 생성 중임을 화면에 표시하고, 해당 요청이 끝날 때까지 중복 제출을 막는다.
6. 성공하면 입력과 생성된 뒷부분이 합쳐진 전체 코드를 결과 영역에 표시한다.
7. 입력 오류나 생성 실패가 발생하면 이유를 표시하고, 입력을 보존하여 수정 또는 재시도할 수 있게 한다.

필수 화면 요소는 코드 입력창, `입력 최대 256토큰 · 추가 생성 최대 256토큰` 안내, 생성 버튼, 처리 상태·오류 안내, 전체 코드 결과 영역이다. 별도 페이지나 부가 기능은 요구하지 않는다.

## 5. 입력 제한 요구사항

### 5.1 계산 방법

서버는 `codebot/merge_rules.pkl`로 로드한 `BPETokenizer`를 사용해 실제 입력 문자열의 토큰 수를 계산한다.

```python
input_tokens = len(tokenizer.encode(user_code))
```

- 유효 입력은 내용이 있는 코드이며 토큰 수가 1 이상 256 이하인 문자열이다.
- 빈 문자열과 공백·탭·줄바꿈만 있는 입력은 생성하지 않고 안내한다.
- 공백 여부 확인과 별개로 실제 모델 입력의 앞뒤 공백, 들여쓰기, 탭, 줄바꿈은 제거하거나 변경하지 않는다.
- 코드의 일부분을 입력하는 서비스이므로 Python 구문이 미완성이라는 이유로 거절하지 않는다.
- 257토큰 이상이면 추론을 실행하지 않고 초과 오류를 반환한다.
- 초과 입력을 자동으로 자르지 않는다. 사용자가 직접 수정할 수 있도록 입력을 보존한다.
- 오류에는 실제 입력 토큰 수와 허용 최대값 256을 안내한다.
- 문자 수·바이트 수·줄 수 또는 다른 모델의 토크나이저로 대체하지 않는다.
- 프론트엔드 검사 여부와 관계없이 서버에서 최종 검증한다. 실시간 토큰 카운터는 필수 기능이 아니다.

### 5.2 입력과 생성 한도의 관계

입력 한도와 추가 생성 한도는 각각 256토큰이다. 입력 예산을 `256 - 256 = 0`으로 계산하지 않는다.

예를 들어 입력이 256토큰이고 종료 토큰이 나오지 않으면, 최대 256토큰을 추가 생성하여 내부 토큰 시퀀스는 최대 512토큰이 될 수 있다. 다만 각 생성 단계에서 모델이 참조하는 문맥은 최근 256토큰으로 제한된다. 오래된 입력은 추론 문맥에서 제외될 수 있지만, 화면에 표시하는 전체 결과에서는 유지된다.

문자열을 다시 토큰화한 결과가 아니라, 실제 생성 반복에서 추가한 토큰 수를 생성 한도의 기준으로 삼는다.

## 6. 코드 생성 요구사항

- 서버에서 `GPT.load_from()`으로 `model_pretrain.pt`를 로드하고 기존 토크나이저와 생성 함수를 재사용한다.
- 모델과 토크나이저는 서버 초기화 시 준비하여 요청마다 다시 로드하지 않는다.
- 사용자 입력을 그대로 프롬프트로 전달한다. SFT용 `### Instruction` / `### Response` 포맷을 추가하지 않는다.
- `generate()` 호출 시 `max_new_tokens=256`을 명시한다.
- 온도는 기존 사전학습 추론 예시와 함수 기본값인 `temperature=1.0`을 유지한다. 화면에 설정 기능을 추가하지 않는다.
- 기존 `model.eval()` 및 기울기 계산 비활성화 동작을 유지한다.
- 종료 토큰이 생성되면 즉시 종료하며, 생성된 종료 토큰은 결과에 포함하지 않는다.
- 즉시 종료되어 추가 코드가 비어 있더라도 오류로 취급하지 않고 전체 결과인 입력 코드를 표시한다.
- 문맥이 넘치면 기존 생성 함수의 최근 문맥 참조 방식을 유지한다.
- 생성된 코드를 실행하거나 자동 수정하지 않는다.
- 모델의 생성 결과가 항상 문법적으로 올바르거나 의도에 맞는다는 것을 보장하지 않는다.

## 7. 프론트엔드·백엔드 연동 요구사항

| 구분 | 필수 내용 |
| --- | --- |
| 요청 | 사용자 입력 코드 문자열 |
| 서버 검증 | 문자열 여부, 빈 내용 여부, 실제 입력 토큰 수 |
| 성공 응답 | 입력과 생성된 뒷부분을 포함한 전체 코드 문자열 |
| 입력 초과 응답 | 초과 사유, 실제 입력 토큰 수, 입력 한도 256 |
| 기타 실패 응답 | 사용자가 이해할 수 있는 실패 안내 |

- 인증 없이 생성 요청을 보낼 수 있어야 한다.
- 입력·생성 한도와 모델은 서버에서 관리하며, 요청으로 임의 변경할 수 없게 한다.
- 결과의 공백과 줄바꿈을 보존하고, HTML로 실행하지 않고 텍스트로 표시한다.
- 모델 로드 실패나 추론 오류를 성공 결과로 표시하지 않는다.
- 구현 전 사용자 확인으로 확정한 API는 `POST /api/generate`이다. 요청은 `{"code":"입력"}`, 성공 응답은 `{"code":"전체 결과"}`이며, 입력 오류는 422, 생성 실패는 500, 다른 요청 생성 중에는 503을 반환한다.

## 9. 완료 및 검증 기준

구현 후 아래 항목으로 최소 기능을 검증한다. 테스트 입력의 토큰 수는 반드시 서비스와 동일한 토크나이저로 확인한다.

| 번호 | 검증 상황 | 통과 기준 |
| --- | --- | --- |
| 1 | 비로그인 상태로 화면 접근 및 생성 요청 | 인증 요구 없이 입력과 생성 가능 |
| 2 | 서버에서 모델 로드 | `model_pretrain.pt` 로드 성공, 문맥 길이 256 확인 |
| 3 | `def` 같은 미완성 코드 입력 | 구문 완성 여부 검사 없이 실제 모델을 호출하고 전체 결과 표시 |
| 4 | 들여쓰기·탭·줄바꿈이 있는 입력 | 입력이 변경 없이 모델에 전달되고 결과 표시에서 형식 유지 |
| 5 | 빈 입력 또는 공백만 있는 입력 | 추론하지 않고 입력 안내 표시 |
| 6 | 정확히 256토큰인 입력 | 입력 검증 통과 및 생성 처리 |
| 7 | 257토큰 이상인 입력 | 추론하지 않고 실제 토큰 수와 최대 256토큰 안내; 원문 보존 |
| 8 | 한글 주석 등 다중 바이트 문자를 포함한 입력 | 문자 수가 아닌 기존 BPE 토큰 수로 판단 |
| 9 | 종료 토큰이 나오지 않는 생성 경로 | 생성 반복이 최대 256회에서 종료 |
| 10 | 종료 토큰이 조기에 나오는 생성 경로 | 즉시 정상 종료하고 생성된 종료 토큰을 표시하지 않음 |
| 11 | 입력과 생성의 합이 256토큰을 넘는 경로 | 각 모델 호출의 문맥이 256 이하이고, 결과에는 원래 입력 유지 |
| 12 | 생성 버튼 연속 클릭 | 처리 중 같은 화면에서 중복 요청하지 않음 |
| 13 | 모델 추론 실패 | 실패 안내 표시, 입력 보존, 재시도 가능 |
| 14 | 결과 표시 | 입력 중복 연결 없이 전체 코드가 텍스트로 표시됨 |

실제 모델을 사용하는 정상 생성 1건 이상을 포함하여 React → FastAPI → 코드봇 → 결과 화면의 연결을 확인한다. 종료 토큰 및 최대 반복처럼 확률에 좌우되는 경계 조건은 제어 가능한 테스트로 검증할 수 있다. 코드 정확도나 특정 응답 시간은 현재 완료 기준으로 확정하지 않는다.

## 10. 추가 결정 처리 원칙

배포 장소·공개 주소, 서버 사양, 동시 요청 처리 정책, 시간 제한, 상세 API 규격 등 이번 대화에서 확정하지 않은 사항이 필요해지면 먼저 사용자에게 질문한다. 요구사항이나 기능을 임의로 추가하지 않는다. 공개 배포 및 운영 정책은 이 문서만으로 확정된 것으로 간주하지 않는다.

구현 시작 전 사용자 승인으로 `codebot_web` 폴더, 로컬 실행, Vite 사용, 한 번에 한 요청 생성 및 동시 요청 시 503 재시도 안내, 별도 생성 시간 제한 없음이 추가 확정되었다.
